# Dataset and Model Licensing for a Public Speculative-Decoding Benchmark Repo

Scope: committing a small `prompts.json` (10 prompts each from HumanEval, GSM8K, and one chat/instruction set) plus model outputs to a public GitHub repo; models (Qwen2.5-3B-Instruct, Qwen2.5-0.5B-Instruct) are downloaded, not redistributed. Checked September 2026 against the Hugging Face API metadata, the GitHub LICENSE files, and the licence texts. **This is not legal advice.** Facts come from the licence texts and metadata. Anything marked "Inference" is interpretation.

---

## 1. HumanEval (openai/human-eval, HF openai/openai_humaneval)

### Takeaway
HumanEval is under the MIT licence both on GitHub and on the HF dataset card. You can copy 10 problems into the repo if you keep OpenAI's copyright line and the MIT permission notice.

### Cited Findings
- GitHub repo LICENSE is "The MIT License", "Copyright (c) OpenAI (https://openai.com)" — [openai/human-eval LICENSE](https://raw.githubusercontent.com/openai/human-eval/master/LICENSE)
- HF dataset `openai/openai_humaneval` metadata: `license: mit` (tag `license:mit`) — [HF API openai/openai_humaneval](https://huggingface.co/api/datasets/openai/openai_humaneval)
- The standard MIT condition says the copyright notice and permission notice "shall be included in all copies or substantial portions of the Software". It has no share-alike, non-commercial or field-of-use terms — [MIT licence text (OSI)](https://opensource.org/license/mit)

### Inferences
- 10 of the 164 problems is arguably not a "substantial portion". Even so, the safest practice is to reproduce the OpenAI MIT copyright and permission notice in a DATA_LICENSES/NOTICE file. It costs nothing.
- HumanEval prompts contain function signatures and docstrings. The canonical solutions and tests are not needed for speculative-decoding throughput, so leaving them out keeps the copied portion small.
- Publishing HumanEval problems on GitHub is already very common, so the idea that this "leaks" the benchmark does not matter here: the benchmark measures speed, not accuracy.

### Gaps
- No separate HumanEval terms of use were found beyond MIT.

## 2. GSM8K (openai/grade-school-math, HF openai/gsm8k)

### Takeaway
GSM8K is under the MIT licence ("Copyright (c) 2021 OpenAI"). Copying 10 problems is permitted if you keep the notice. Cite Cobbe et al. 2021 as a courtesy.

### Cited Findings
- GitHub LICENSE is "MIT License", "Copyright (c) 2021 OpenAI" — [openai/grade-school-math LICENSE](https://raw.githubusercontent.com/openai/grade-school-math/master/LICENSE)
- HF dataset `openai/gsm8k` metadata: `license: ["mit"]` — [HF API openai/gsm8k](https://huggingface.co/api/datasets/openai/gsm8k)

### Inferences
- The attribution practice is the same as for HumanEval: include the MIT notice and cite the paper ("Training Verifiers to Solve Math Word Problems", Cobbe et al., 2021, arXiv:2110.14168). The citation is academic custom, not a licence requirement.

### Gaps
- None material.

## 3. Chat/instruction prompt sets: licences and cleanest choice

### Takeaway
The cleanest sources for redistributing 10 chat prompts in an MIT/Apache repo are **MT-Bench questions** (in the Apache-2.0 FastChat repo; the HF mirror HuggingFaceH4/mt_bench_prompts is also tagged apache-2.0), **OpenAssistant oasst1** (Apache-2.0) and **IFEval** (Apache-2.0).
- **Avoid:** Alpaca and AlpacaEval (CC BY-NC 4.0), lmsys-chat-1m (licence forbids redistribution) and ShareGPT (no licence).
- **Workable with caveats:** Dolly-15k (CC BY-SA 3.0), which is usable only if the file keeps CC BY-SA terms.

MT-Bench is also the chat subset of Spec-Bench, so it is the best choice for comparability too.

### Cited Findings
- **databricks-dolly-15k**: `license: cc-by-sa-3.0` — [HF API databricks/databricks-dolly-15k](https://huggingface.co/api/datasets/databricks/databricks-dolly-15k)
  - CC BY-SA 3.0 §4(b): Adaptations must be distributed under the same licence or a compatible CC licence with the same elements.
  - §4(c): attribution must give the creator's name, the title, the URI, credit for how the work was adapted, and a copy or URI of the licence.
  - The licence defines "Collection" (the work included "in its entirety in unmodified form" alongside other works) separately from "Adaptation" — [CC BY-SA 3.0 legal code](https://creativecommons.org/licenses/by-sa/3.0/legalcode)
- **Stanford Alpaca** (`tatsu-lab/alpaca`): CC BY-NC 4.0. The data was generated by OpenAI `text-davinci-003` — [HF tatsu-lab/alpaca](https://huggingface.co/datasets/tatsu-lab/alpaca)
- **AlpacaEval** (`tatsu-lab/alpaca_eval`): CC-BY-NC-4.0. It has 805 instructions drawn from self-instruct, OASST, Anthropic Helpful, Vicuna and Koala — [HF tatsu-lab/alpaca_eval](https://huggingface.co/datasets/tatsu-lab/alpaca_eval)
- **MT-Bench**:
  - The questions live at `fastchat/llm_judge/data/mt_bench/question.jsonl` (48,929 bytes) in lm-sys/FastChat — [GitHub API listing](https://api.github.com/repos/lm-sys/FastChat/contents/fastchat/llm_judge/data/mt_bench)
  - The FastChat repo licence is Apache-2.0 — [GitHub API FastChat licence](https://api.github.com/repos/lm-sys/FastChat/license)
  - The FastChat llm_judge README calls MT-bench "a set of challenging multi-turn open-ended questions" (80 questions) and has no separate data licence statement — [FastChat llm_judge README](https://github.com/lm-sys/FastChat/blob/main/fastchat/llm_judge/README.md)
  - The HF mirror `HuggingFaceH4/mt_bench_prompts` is tagged `apache-2.0` — [HF API](https://huggingface.co/api/datasets/HuggingFaceH4/mt_bench_prompts)
- **OpenAssistant oasst1**: `license: apache-2.0` — [HF API OpenAssistant/oasst1](https://huggingface.co/api/datasets/OpenAssistant/oasst1)
- **IFEval** (`google/IFEval`): `license: apache-2.0` — [HF API google/IFEval](https://huggingface.co/api/datasets/google/IFEval)
- **lmsys-chat-1m**: the licence agreement says "You should not distribute, copy, disclose, assign, sublicense, embed, host, or otherwise transfer the dataset to any third party". The grant is a "limited, non-exclusive, non-transferable, non-sublicensable license", and the providers can demand deletion of all copies "in whole or in part" — [HF lmsys/lmsys-chat-1m](https://huggingface.co/datasets/lmsys/lmsys-chat-1m)

### Inferences
- **Dolly (CC BY-SA 3.0):**
  - 10 verbatim prompts copied into a JSON file next to other datasets' prompts is arguably a "Collection" (unmodified works in a compilation) rather than an "Adaptation", so share-alike would not reach the MIT code.
  - The Dolly-derived entries themselves must still stay under CC BY-SA 3.0 with full §4(c) attribution.
  - Mixing licences inside one `prompts.json` is legal but messy. If Dolly is used, it is cleaner to keep it in a separate file (for example `prompts/dolly.json`) marked CC BY-SA 3.0.
  - Model outputs generated from Dolly prompts are not obviously Adaptations of the prompts, but this is unsettled.
- **Alpaca and AlpacaEval (CC BY-NC):**
  - Redistribution in a public repo is allowed for non-commercial purposes with attribution. However, a CC BY-NC subset inside an MIT repo creates a non-commercial island that downstream users can easily miss.
  - Alpaca content is also OpenAI model output, which brings the OpenAI terms question the brief raises.
  - Not recommended.
- **lmsys-chat-1m:** committing even 10 conversations appears to breach the "should not distribute, copy … any third party" term. Exclude it.
- **ShareGPT:** no licence exists, the data was scraped from users' shared ChatGPT conversations, and it may contain personal data. Exclude it.
- **Best pick for comparability and licensing:** MT-Bench first-turn questions.
  - Apache-2.0 is compatible with an MIT repo when you keep the licence and a notice.
  - These questions are exactly the Spec-Bench "multi-turn conversation" subset.
  - Speculative-decoding papers (Medusa, EAGLE, Spec-Bench) commonly report on MT-Bench.
- **Alternatives:** oasst1 or IFEval, both Apache-2.0.
- **Apache-2.0 §4 obligations** apply to "the Work or Derivative Works" when redistributed:
  - give recipients a copy of the licence;
  - keep the attribution notices;
  - carry forward the NOTICE file, if the upstream has one;
  - mark any modified files.
  - Source: [Apache-2.0 text](https://www.apache.org/licenses/LICENSE-2.0)

### Gaps
- **Vicuna-80 ("Vicuna bench"):** historically in FastChat (Apache-2.0 repo), but no current file path or separate licence statement was verified in this pass. It is also largely superseded by MT-Bench.
- **ShareGPT:** no authoritative licence page was found. "No licence" is the observed state of the community dumps (not re-verified here).
- **OpenAI terms of use for Alpaca:** the Alpaca HF card excerpt retrieved did not quote specific OpenAI terms. The claim that "Alpaca is non-commercial partly because of OpenAI ToS" comes from the Stanford Alpaca release, which was not re-fetched here.

## 4. Spec-Bench (hemingkx/Spec-Bench)

### Takeaway
The Spec-Bench repo is Apache-2.0. Its data has 480 prompts (80 × 6 categories) at `data/spec_bench/question.jsonl`, and it is the de facto standard for comparing speculative-decoding methods.
- **Comparability:** taking the 10 GSM8K and 10 chat prompts from Spec-Bench's own MT-bench and GSM8K subsets gives direct comparability with published results.
- **Licensing:** the per-item licences come from each upstream dataset. Some of those are less clean (NQ/DPR are CC BY-SA 3.0; the CNN/DM article text is third-party news copyright).

### Cited Findings
- Repo licence is Apache-2.0 ("Apache License, Version 2.0, January 2004") — [Spec-Bench LICENSE](https://raw.githubusercontent.com/hemingkx/Spec-Bench/main/LICENSE); [GitHub repo](https://github.com/hemingkx/Spec-Bench)
- The question file is `data/spec_bench/question.jsonl` (698,768 bytes) — [GitHub API listing](https://api.github.com/repos/hemingkx/Spec-Bench/contents/data/spec_bench)
- "Spec-Bench encompasses six distinct subtasks: multi-turn conversation, translation, summarization, question answering, mathematical reasoning, and retrieval-augmented generation. We composed Spec-Bench by randomly selecting 80 instances from each of six widely used datasets." — [Xia et al., arXiv:2401.07851 (ACL Findings 2024)](https://arxiv.org/html/2401.07851)
- Category sources, per the same paper: MT-bench, WMT14 DE-EN, CNN/Daily Mail, Natural Questions, GSM8K, and DPR (top-5 retrieved docs concatenated with NQ questions) — [arXiv:2401.07851](https://arxiv.org/html/2401.07851)
- The primary target model in the Spec-Bench repo is Vicuna-7B-v1.3. It evaluates EAGLE-1/2/3, Hydra, Medusa, Prompt Lookup Decoding, Lookahead and others — [GitHub repo](https://github.com/hemingkx/Spec-Bench)
- Natural Questions: `license: cc-by-sa-3.0` — [HF API natural_questions](https://huggingface.co/api/datasets/google-research-datasets/natural_questions)
- CNN/DailyMail (`abisee/cnn_dailymail`): tagged `apache-2.0` — [HF API](https://huggingface.co/api/datasets/abisee/cnn_dailymail)

### Inferences
- **Use the Spec-Bench subsets for the categories you need.**
  - Pick the MT-bench and GSM8K items by `question_id`/category from `question.jsonl`. You can then say "prompts are a subset of Spec-Bench", and readers can compare against the Spec-Bench leaderboard categories.
  - Spec-Bench has no HumanEval/code category, so HumanEval remains a separate MIT source.
- **Licence per item:**
  - MT-bench items: Apache-2.0 (FastChat).
  - GSM8K items: MIT.
  - Spec-Bench's own Apache-2.0 licence covers its compilation and code.
  - Attribute Spec-Bench (Apache-2.0) and the upstream datasets.
- **Categories to avoid redistributing** (if you want a clean licence story):
  - summarisation: CNN/DM news articles; the Apache-2.0 tag covers the dataset scripts and packaging, not necessarily the article text copyright;
  - RAG: Wikipedia passages under CC BY-SA;
  - QA: NQ, CC BY-SA 3.0.
- **Alternative:** have the benchmark script download `question.jsonl` at runtime rather than committing it. This avoids redistribution entirely while keeping comparability.
- **Caveat:** Spec-Bench numbers are for Vicuna-7B, with different hardware and models. Using its prompts gives prompt-set comparability, not number-for-number comparability.

### Gaps
- No per-category licence statement was found in the Spec-Bench README or data folder. The repo's Apache-2.0 licence does not relicense upstream content.
- The WMT14 news-test licence terms were not verified (WMT data is generally distributed for research use).

## 5. Qwen2.5-3B-Instruct vs Qwen2.5-0.5B-Instruct licences

### Takeaway
- **Qwen2.5-0.5B-Instruct** is Apache-2.0.
- **Qwen2.5-3B-Instruct** is under the **Qwen RESEARCH LICENSE AGREEMENT** (19 Sept 2024). Its grant is "FOR NON-COMMERCIAL PURPOSES ONLY", and Non-Commercial means "for research or evaluation purposes only".
- A public, non-commercial speed benchmark that downloads the model and publishes outputs and timings fits within "research or evaluation". No clause was found that restricts publishing results or outputs.

### Cited Findings
- Qwen2.5 blog: "All our open-source models, except for the 3B and 72B variants, are licensed under Apache 2.0." — [Qwen2.5 blog](https://qwenlm.github.io/blog/qwen2.5/)
- Qwen2.5-0.5B-Instruct model card metadata: `license: apache-2.0` — [HF API Qwen2.5-0.5B-Instruct](https://huggingface.co/api/models/Qwen/Qwen2.5-0.5B-Instruct)
- Qwen2.5-3B-Instruct LICENSE is the "Qwen RESEARCH LICENSE AGREEMENT", dated September 19, 2024 — [Qwen2.5-3B-Instruct LICENSE](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct/raw/main/LICENSE)
- Definitions and grant:
  - "'Non-Commercial' shall mean for research or evaluation purposes only."
  - Rights are granted "FOR NON-COMMERCIAL PURPOSES ONLY".
  - "If you are commercially using the Materials, you shall request a license from us".
  - "Materials" means "Alibaba Cloud's proprietary Qwen and Documentation".
  - Source: [same LICENSE](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct/raw/main/LICENSE)
- Redistribution (only if you redistribute the Materials): give recipients the Agreement, mark changed files with "prominent notices", and retain the notice "Qwen is licensed under the Qwen RESEARCH LICENSE AGREEMENT, Copyright (c) Alibaba Cloud" — [same LICENSE](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct/raw/main/LICENSE)
- Outputs:
  - The licence mentions outputs in the disclaimer ("NO WARRANTY … FOR THE SAFETY OR STABILITY OF THE MATERIALS AND ANY OUTPUT THEREFROM").
  - It also has a training clause: "If you use the Materials or any outputs or results therefrom to create, train, fine-tune…" an AI model, you must "prominently display 'Built with Qwen' or 'Improved using Qwen'".
  - Source: [same LICENSE](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct/raw/main/LICENSE)
- Termination: on breach, the licensee must "delete and cease use of the Materials" — [same LICENSE](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct/raw/main/LICENSE)

### Inferences
- **Downloading, not redistributing.** Because the repo only downloads the weights (for example via `from_pretrained`), the §3 redistribution duties (ship the Agreement, keep the notice) are not strictly triggered. Still, a README line stating the licence of each model is good practice.
- **Publishing outputs.** Publishing generated outputs and timing results from a research benchmark is "research or evaluation". Neither the extracted text nor the Qwen2.5 announcement found any clause that forbids publishing outputs or benchmark results.
- **"Built with Qwen" labelling.** This is triggered only if outputs are used to create, train or fine-tune a model. It could matter if someone later fine-tunes a drafter on the committed Qwen-3B outputs.
  - Adding a note such as "outputs of Qwen2.5-3B-Instruct are subject to the Qwen Research License; if used to train a model, 'Built with Qwen' labelling applies" is a prudent interpretation.
- **Commercial reuse.** The Qwen-3B outputs directory should not be presented as MIT-licensed without qualification.
  - The MIT repo licence covers the code. Committed Qwen-3B outputs are better marked as "generated by Qwen2.5-3B-Instruct (Qwen Research License, non-commercial)".
  - This is conservative: it is unsettled whether model outputs carry copyright at all.
- **Option for fully permissive licensing:** swap the target model to Qwen2.5-1.5B-Instruct or Qwen2.5-7B-Instruct (both Apache-2.0 per the blog statement). Keep Qwen2.5-0.5B-Instruct as the drafter, since it shares the tokenizer family.

### Gaps
- The full verbatim text of every clause of the Qwen Research License was not extracted, only the summarised and quoted parts above. Read the whole LICENSE file before release.
- No Alibaba/Qwen statement was found that specifically addresses publishing benchmark outputs.

## 6. Recommended attribution practice (DATA_LICENSES / NOTICE)

### Takeaway
Keep the repo code under MIT or Apache-2.0. Add a `DATA_LICENSES.md` (or `NOTICE`) that lists, for each source in `prompts.json`: the dataset name, URL, copyright holder, licence with a link, how many items were used and how they were selected, and whether items were modified. Add a separate section for the model licences and the status of the outputs.

### Cited Findings
- MIT requires the copyright and permission notice to be included in all copies or substantial portions — [MIT licence (OSI)](https://opensource.org/license/mit)
- Apache-2.0 §4 requires giving a copy of the licence, retaining attribution notices, and carrying forward any NOTICE file contents in Derivative Works — [Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0)
- CC BY-SA 3.0 §4(c) requires the creator's name, the title, the URI, credit for how the work was adapted, and the licence URI; §4(b) requires share-alike for Adaptations — [CC BY-SA 3.0 legal code](https://creativecommons.org/licenses/by-sa/3.0/legalcode)

### Inferences
- **Suggested structure** (interpretation, not a legal template):
  1. `LICENSE`: MIT, for the repo code.
  2. `DATA_LICENSES.md` with:
     - **HumanEval:** 10 items, `task_id` list, MIT, "Copyright (c) OpenAI", plus the full MIT text.
     - **GSM8K:** 10 items, test-split indices, MIT, "Copyright (c) 2021 OpenAI", plus the MIT text.
     - **MT-Bench** (via FastChat or Spec-Bench): 10 `question_id`s, Apache-2.0, copyright LMSYS/FastChat authors, plus a link to the Apache-2.0 text. If the items were taken from Spec-Bench's `question.jsonl`, also credit Spec-Bench (Apache-2.0, Xia et al. 2024).
     - Citation BibTeX for each dataset paper.
  3. **Model section:**
     - Qwen2.5-0.5B-Instruct: Apache-2.0.
     - Qwen2.5-3B-Instruct: Qwen Research License Agreement (non-commercial: research/evaluation only).
     - Weights are not redistributed.
     - Committed outputs from the 3B model are provided for research/evaluation. Note the "Built with Qwen" condition if they are used for training.
  4. In `prompts.json`, give each record `source`, `source_id` and `license` fields, so provenance survives if the file is copied elsewhere.
- **Keep sources with different licences separable.** Do not mix sources that need share-alike (Dolly/NQ) or non-commercial terms (Alpaca/AlpacaEval) into the same file as MIT/Apache items. That avoids licence contamination arguments.

### Gaps
- No authoritative community standard for "DATA_LICENSES" files was researched. The structure above is a practice recommendation derived from the licence obligations.
